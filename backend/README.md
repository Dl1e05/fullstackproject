# Шаг — backend

FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL. Зависимости — через [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env
docker compose up -d db
uv sync
uv run alembic upgrade head
uv run python -m app.seed
uv run python -m app.seed --demo
uv run fastapi dev app/main.py      # http://localhost:8000/docs
uv run pytest
uv run ruff check . && uv run ruff format .
```

## Структура

```
app/
  main.py      приложение, CORS
  config.py    настройки из .env
  db.py        engine, сессия, Base
  models/      ORM-модели
  api/         роутеры
alembic/       миграции
```

Контракт API описан в комментарии в начале `frontend/src/services/api.js`.

## Прогресс и итоговые тесты

- `GET /users/me/progress` возвращает `completed`, `saved`, `last` и `quiz` по курсам. Для `quiz` score и total берутся из одной лучшей попытки по доле правильных ответов; `passed` остается true, если успешной была любая попытка.
- `GET /users/me/stats` возвращает `lessonsDone`, `coursesDone` и `saved`.
- `PUT /courses/{course_id}/lessons/{lesson_id}/completion` идемпотентно отмечает урок завершенным.
- `PUT /courses/{course_id}/lessons/{lesson_id}/visit` сохраняет последний открытый урок.
- `PUT /users/me/saved/{course_id}` добавляет курс в избранное; `DELETE` удаляет его.
- `DELETE /users/me/progress` очищает прогресс, избранное и результаты итоговых тестов текущего пользователя. Покупки не затрагиваются.
- `POST /courses/{course_id}/quiz/attempts` принимает `{ "answers": [{ "exerciseId": "...", "optionId": "..." }] }`. Сервер проверяет полный набор уникальных вопросов и вариантов, вычисляет результат и проходной балл 70%. Авторизованная попытка сохраняется; гостю возвращается результат без сохранения.
- Для авторизованной попытки можно передать `clientAttemptId` с UUID. Повтор с тем же ID и теми же ответами возвращает сохраненный результат со статусом `200`; повторное использование ID с другими ответами возвращает `409`. Без ID сохраняется прежнее поведение. Попытки гостя не сохраняются.
- `GET /courses/{course_id}/quiz/attempts?limit=20&offset=0` возвращает `{ "items": [], "total": 0, "limit": 20, "offset": 0 }` для истории текущего пользователя. `limit` от 1 до 100, `offset` не меньше 0.

Прогресс и избранное требуют авторизации. Гостям по-прежнему доступны бесплатные курсы и первый preview-урок платного курса. Гость может пройти итоговый тест бесплатного курса, но результат не сохраняется; тест платного курса требует покупки. Frontend использует эти маршруты для прогресса, статистики и истории тестов.

## Восстановление аккаунта и покупка

- `POST /auth/forgot-password` принимает `{ "email": "..." }` и возвращает `202` с `null` для существующего или неизвестного адреса. Ошибка почтового транспорта не меняет этот ответ.
- `POST /auth/reset-password` принимает `{ "token": "...", "password": "..." }` и возвращает `204` при успехе. Токен действует 30 минут и используется один раз; неверный, истекший или использованный токен дает `400`.
- `POST /auth/logout` возвращает `204`; отсутствующий, отозванный или недействительный токен дает `401`.
- `POST /courses/{course_id}/purchase` остается демо-оплатой и возвращает профиль `UserRead`. `MockPaymentAdapter` использует детерминированный mock-результат и не подключается к платежному провайдеру.

`get_email_sender` предоставляет `MockEmailSender` без сетевой доставки. В dev или интеграционном smoke можно переопределить зависимость на recording sender; reset token не возвращается в HTTP-ответе.

## Настройки безопасности

`SECRET_KEY` должен быть непустым во всех окружениях и иметь не меньше 32 символов вне `APP_ENV=dev`. Значение `change-me` допустимо только в dev. `ACCESS_TOKEN_EXPIRE_MINUTES` должен быть положительным.

Новые переменные для SMTP и платежного провайдера не добавлены. Production-восстановление пароля требует реализации и конфигурации почтового провайдера.

## Demo seed

`uv run python -m app.seed` добавляет отсутствующий контент курсов из `app/seed/data.json`. Флаг `--demo` дополнительно создает синтетические аккаунты, покупки, избранные курсы, прогресс уроков, завершения и попытки итоговых тестов.

Seed запускается только при `APP_ENV=dev`. Скрипт не меняет существующие строки и не сбрасывает данные. Если demo email уже существует, но имя или пароль не совпадают с seed marker, аккаунт и связанные демо-данные пропускаются. Попытка теста добавляется, только если у demo аккаунта еще нет попытки по этому курсу.

Локальный demo login:

- `demo@example.com` / `DemoPass123` - бесплатные курсы и история обучения.
- `demo.paid@example.com` / `DemoPass123` - покупка курса `ai` и история обучения.

Это синтетические данные для локальной базы разработки. Скрипт не печатает логины и пароли, не создает access/reset токены и не пишет строки в `revoked_tokens` или `password_reset_tokens`. Новые demo users получают значение `token_version=0` из default базы; существующие записи не меняются. Alembic запускается отдельно для создания или обновления схемы. Скрипт не редактирует `alembic_version`.
